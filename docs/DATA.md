# The Bank Kenari data

Generated by `node scripts/verify.mjs --facts`. Everything is invented. Data is as of 2026-10-31.

## Tables and row counts

- **branches**: 12 rows. Bank branches. KC is a main branch and KCP is a smaller sub-branch.
  - Columns: `branch_id` (unique ID), `branch_name` (branch name), `city` (city), `region` (region)
- **collectors**: 33 rows. People and agencies who work overdue loans, plus their managers.
  - Columns: `collector_id` (unique ID), `collector_name` (name), `team` (Desk Call, Field, Agency, Management), `branch_id` (links to branches), `supervisor_id` (links to another collector, their boss), `hired_date` (start date)
- **customers**: 423 rows. Borrowers. City is typed by hand, so it can be messy.
  - Columns: `customer_id` (unique ID), `full_name` (name), `city` (home city), `phone` (phone, can be NULL), `email` (email, can be NULL), `employment` (Payroll, Non-Payroll, Self-employed), `joined_date` (became a customer)
- **loans**: 502 rows. One row per loan, as it stood on 31 Oct 2026.
  - Columns: `loan_id` (unique ID), `customer_id` (links to customers), `branch_id` (links to branches), `product` (KPR home, KKB vehicle, KTA personal, Kartu Kredit card), `disbursed_date` (when the money went out), `principal` (original amount, Rp), `outstanding` (balance still owed, Rp), `installment` (monthly payment, Rp), `interest_rate` (percent per year), `dpd` (days past due), `collectibility` (Kol grade, 1 to 5), `status` (Active, Restructured, Written Off), `write_off_date` (date written off, else NULL)
- **payments**: 4436 rows. Money received on loans.
  - Columns: `payment_id` (unique ID), `loan_id` (links to loans), `payment_date` (date), `amount` (Rp), `channel` (Auto-debit, Mobile, ATM, Teller, Collector)
- **collection_activities**: 2166 rows. One row per contact attempt on an overdue loan.
  - Columns: `activity_id` (unique ID), `loan_id` (links to loans), `collector_id` (links to collectors, NULL if automatic), `activity_date` (date), `activity_type` (Auto SMS, Call, WhatsApp, Visit, SP Letter), `result` (PTP, Contacted, No Answer, Paid, and others), `ptp_date` (promised pay date, NULL unless PTP), `ptp_amount` (promised Rp, NULL unless PTP)
- **loan_snapshots**: 5015 rows. Each loan at each month end, Jan to Oct 2026. Use it to look back in time.
  - Columns: `snapshot_month` (for example 2026-10), `loan_id` (links to loans), `dpd` (days past due then), `collectibility` (Kol grade then), `outstanding` (balance then, Rp)
- **loan_assignments**: 335 rows. Which collector holds which loan, and from when to when.
  - Columns: `assignment_id` (unique ID), `loan_id` (links to loans), `collector_id` (links to collectors), `assigned_date` (start date), `unassigned_date` (end date, NULL if still assigned)
- **batch_runs**: 606 rows. Nightly data feeds into the collection system.
  - Columns: `run_id` (unique ID), `run_date` (date of the run), `feed_name` (CORE_LOANS or PAYMENTS), `rows_sent` (rows the source sent), `rows_loaded` (rows that arrived), `status` (SUCCESS or FAILED), `finished_time` (time it finished, HH:MM)

## How tables connect

- loans.customer_id → customers.customer_id
- loans.branch_id → branches.branch_id
- collectors.branch_id → branches.branch_id
- collectors.supervisor_id → collectors.collector_id
- payments.loan_id → loans.loan_id
- collection_activities.loan_id → loans.loan_id
- collection_activities.collector_id → collectors.collector_id
- loan_snapshots.loan_id → loans.loan_id
- loan_assignments.loan_id → loans.loan_id
- loan_assignments.collector_id → collectors.collector_id
